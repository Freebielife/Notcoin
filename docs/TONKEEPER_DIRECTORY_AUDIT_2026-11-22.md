# Аудит идентификации TON-адресов — Notcoin, 22.11.2026

## Приоритет источников

1. **Tonkeeper**: [tonkeeper/ton-assets/accounts.json](https://github.com/tonkeeper/ton-assets/blob/main/accounts.json).
   Сравниваем ТОЧНЫЙ нормализованный raw-адрес TON (`0:<64 hex>`), а не
   совпадение имени, суммы баланса или похожих транзакций. Это внешняя
   атрибуция, не криптографическое доказательство оператора.
2. **Дополнительные подтверждённые источники**, только когда точный
   адрес не найден в Tonkeeper: именованные адреса, ранее подтверждённые
   по ссылкам на блокчейн-обозреватели; специализированные интерфейсы
   TonAPI; TON Center. Записываем происхождение метки.
3. **Пользовательские метки** при отсутствии адреса в Tonkeeper —
   отдельно отмеченные внешние утверждения, не равные подтверждению биржей.
4. Неопознанный активный не-wallet контракт отображается как
   «Смарт-контракт», оператор не установлен. Highload/multisig сами
   по себе не доказывают сервисное назначение.

### Реализация

- `common-services.json`: все однозначные записи первичного справочника
  в `directory`, только сервисные в `entries`, конфликтные в `ambiguous`.
- `service_registry.py`: точное сопоставление и строгий список
  типовых имен протоколов, проверка целостности, обновление из первоисточника.
  Сбой сети не должен стирать уже проверенный каталог.
- `observatory.py`: первенство Tonkeeper, затем точные локальные
  подтверждения и классификация через TonAPI / TON Center.
- `web/app.js`: не-сервисные имена доступны для отображения,
  но не превращаются в биржевые кошельки.
- Ограничение автономного `index.html` — 512 000 байт;
  полный каталог и историю храним в `data/snapshot.json` на GitHub.

Данные о конкретных кошельках и рейтингах могут изменяться: адресная
атрибуция проверяется повторно по расписанию, но сам по себе реестр
Tonkeeper не доказывает конечного владельца.
